## Section 1: Security Architecture & Vulnerability Gate

Trivy has been integrated into the GitHub Actions CI/CD pipeline as a strict security gate **before** the container images are pushed to GitHub Container Registry and Docker Hub. 

This ensures that vulnerable images are never admitted into our artifact repositories or deployed to production. The scanner is configured to check both the OS base image packages and the language-specific runtime dependencies (Node.js and Python packages).

**Pipeline Flow:**
```text
Build Local Images -> Trivy Scan (Backend & Frontend) -> Exit Code Check -> Push to Registries
```

## Section 2: Pipeline Configuration Snippet

The security scanner relies on the official Aqua Security Trivy GitHub Action. The gate is explicitly configured to fail the entire pipeline (`exit-code: '1'`) if any actionable `HIGH` or `CRITICAL` vulnerabilities are detected.

```yaml
      - name: Run Trivy Vulnerability Scanner
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: 'backend:scan'
          format: 'table'
          exit-code: '1'
          ignore-unfixed: true
          severity: 'HIGH,CRITICAL'
```

## Section 4: Technical CVE / Vulnerability Analysis

During the pipeline execution, Trivy deeply analyzed our Docker images for known Common Vulnerabilities and Exposures (CVEs). 

- **Backend Scan:** Trivy scanned the `python:3.11-slim` Debian base OS packages along with all pip-installed dependencies (FastAPI, SQLAlchemy, etc.).
- **Frontend Scan:** Trivy scanned the `nginx:alpine` base OS packages and the static assets.

Because we used modern, slim, and recently updated base images (`python:3.11-slim` and `nginxinc/nginx-unprivileged:alpine`), the scan successfully verified that **zero unpatched HIGH or CRITICAL vulnerabilities** were present. 

By passing the `--ignore-unfixed=true` flag, we ensure our CI/CD pipeline does not fail abruptly due to theoretical vulnerabilities that the upstream software vendors (e.g., Debian or Alpine package maintainers) have not yet provided a patch for. If a patchable vulnerability is ever introduced (such as a compromised Python package), Trivy will exit with code `1`, halting the pipeline and forcing the engineering team to upgrade the dependency.
